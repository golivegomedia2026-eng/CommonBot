# CommonBot 通用智能体平台 · 选型与方案

> 状态：P0–P4 与离线包、升级、桌面版已完成；手机客户端和语音未做。实际做法与本稿不同之处以 DECISIONS.md 为准（D16 之后的条目），进度见 PROGRESS.md。日期：2026-11-15。署名：M&J Group
> 本稿中的开源项目许可证、版本和 DGX Spark 上的性能均为撰写时的认识，**动工前要在真机和各项目官方仓库重新核对**。

## 1. 需求与验收链路

| # | 需求 | 验收样例（输入 → 操作 → 输出） |
| --- | --- | --- |
| 1 | 新建智能体并定义其负责的任务 | 填写名称、职责、边界 → 保存 → 得到一个可对话的智能体，超出职责的问题会说明不归它管 |
| 2 | 为智能体建知识库，按知识库回答，也可结合联网 | 上传一批文档 → 提问 → 回答带出处（文档名、页/段）；打开联网后回答同时带网页来源，两类来源分开标注 |
| 3 | 通过通话抽象出能力，生成可独立工作的智能体 | 与「建造师」对话若干轮 → 系统整理出智能体定义并给出试答 → 确认后发布 → 新智能体有自己的入口，可单独使用 |

## 2. 结论：不用开源 bot 平台做底层，自研 Rust 核心 + 开源组件

### 2.1 为什么不直接拿开源平台做底层

| 候选 | 技术栈 | 长处 | 作为底层的问题 |
| --- | --- | --- | --- |
| Dify | Python + Next.js，多容器 | 智能体/工作流/知识库最全 | 许可证有附加条款（多租户、去标识受限）；体量大；与 Rust 基础不合；需求 3 要改到它的核心 |
| RAGFlow | Python，多容器 | 文档解析与检索质量好 | 偏知识库，智能体定义弱；依赖重（ES/Infinity、MinIO 等） |
| FastGPT | TypeScript | 知识库问答成熟 | 许可证限制对外提供服务；同样要二次开发核心 |
| Coze Studio | Go + React | 智能体搭建体验好 | 微服务依赖多；二开语言是 Go |
| AnythingLLM | Node | 轻，MIT，开箱即用 | 智能体能力浅，扩展靠改它的代码 |
| Open WebUI | Python + Svelte | 对话界面成熟 | 是聊天前端，不是智能体平台；许可证有品牌限制 |
| MaxKB | Python | 知识库问答 | GPLv3，衍生产品要同样开源 |

共同问题：

1. **需求 3 是产品的核心差异点，任何现成平台都没有**，都要深改别人的核心代码，之后每次上游升级都要重新合并。
2. 这些平台都是 Python/TS/Go 多容器部署，和「Rust 单二进制、开箱即用、离线可运行」的系列约定相反。
3. 许可证对改名、去标识、对外服务有限制，系列产品署名 M&J Group 会受约束。
4. 需求 1、2 本身并不难：智能体定义是一张表加一段提示词，知识库问答是一条成熟的流水线。真正费工夫的部分（模型推理、向量检索、搜索）可以用组件解决。

所以：**借鉴它们的产品设计，不用它们的代码**；底层能力用下面这些可嵌入或独立运行的组件。

### 2.2 组件选型

| 层 | 首选 | 备选 | 说明 |
| --- | --- | --- | --- |
| 模型推理 | Ollama 起步（装得快、模型管理省事） | vLLM（多人并发时吞吐更好）、llama.cpp server、NVIDIA NIM | 平台只认 OpenAI 兼容接口，推理后端可在界面里换，不绑定某一个 |
| 对话模型 | 30B 级中文强的开源模型（Qwen3 系列）做日常；100B 级（如 gpt-oss-120b）做建造师这类要强推理的环节 | 云端 API 作为可选后备 | Spark 128GB 统一内存放得下，但速度受内存带宽限制，要真机实测后定 |
| 向量化 / 重排 | bge-m3 + bge-reranker-v2-m3 | Qwen3-Embedding / Reranker | 中英日都要覆盖 |
| 向量与全文检索 | LanceDB（Rust 原生、嵌入式，向量 + 全文混合检索，不用多起一个服务） | Qdrant（Rust，独立服务，量大时换） | 检索层做成接口，可替换 |
| 业务数据 | SQLite（智能体、会话、配置、任务） | PostgreSQL（多人、量大时） | 单机单文件，备份简单 |
| 文档解析 | Rust 原生处理 txt/md/docx/xlsx/html/文字版 PDF | 扫描件、复杂版面走文字识别组件（MinerU 或 PaddleOCR，随产品安装） | **这是 Rust 生态的短板**，识别不自己造；具体选哪个要在 Spark 上比过再定 |
| 联网搜索 | SearXNG 自建（聚合多个搜索引擎，不需要密钥） | Tavily / 博查 / Bing 等搜索 API（界面里配密钥） | SearXNG 是 AGPL，按独立服务调用，不并入我们的代码 |
| 网页正文提取 | Rust 实现（readability 类库） | 需要执行脚本的页面走无头浏览器 | 抓取内容当数据处理，不当指令执行 |
| 工具扩展 | MCP（官方 Rust SDK rmcp）：平台作为 MCP 客户端接外部工具 | — | 以后每个发布的智能体也可以反过来暴露成 MCP 服务 |
| 智能体循环 | 自写一个薄的循环（消息 → 调工具 → 再生成），直接走 OpenAI 兼容接口 | Rig（Rust 智能体库） | 循环本身几百行，自写可控；Rig 留作参考，不强依赖 |
| 语音（文字版之后） | 识别：SenseVoice 或 Whisper large-v3；合成：CosyVoice 或 Kokoro；浏览器端 WebRTC/WebSocket 传音频 | — | 作为可选组件，放在文字版跑通之后 |

## 3. 产品形态（已定，见 DECISIONS D4、D7）

**Spark 是主机：上面跑 CommonBot 服务；桌面端、手机端、网页共用同一套界面。**

| 入口 | 形式 | 说明 |
| --- | --- | --- |
| Spark 上的桌面端 | Tauri 2（Linux ARM64） | 自带并启动服务，装完即用；托盘常驻 |
| Mac 桌面端 | Tauri 2（Apple Silicon） | 同样自带服务，可独立运行；也可以填 Spark 的地址当客户端 |
| Windows 桌面端 | Tauri 2 | 不带模型和服务，填 Spark 的地址和访问码后使用 |
| 手机端 | Tauri 2 手机端（Android；iOS 需要 Apple 开发者签名才能装到真机） | 同上，连接 Spark |
| 局域网网页 | 浏览器 | 在设置里打开「局域网访问」后可用，凭访问码进入 |

- 单一主人，不做多账号。服务默认只听本机；打开局域网访问后才对外，并要求访问码。
- 发布出去的智能体走各自的独立链接和 API 密钥，与主人的访问码分开，可单独停用。

```
桌面端 / 手机端 / 浏览器（同一套 Vue 3 界面，简繁英日）
        │  HTTP + SSE（以后语音走 WebSocket）
┌───────▼──────────────────────────────────────────┐
│ CommonBot 服务（Rust，Axum；Spark 上运行）         │
│  智能体管理 │ 对话与循环 │ 知识库 │ 建造师 │ 发布   │
│  SQLite（业务数据）  LanceDB（向量+全文）          │
└───┬───────────┬───────────┬──────────┬───────────┘
    │           │           │          │
 推理后端     联网搜索    文字识别    MCP 工具     云端模型
(Ollama/vLLM) (SearXNG)  (随产品安装)  (可选)    (可选后备)
```

模型：默认全部本地；设置里可加云端模型作后备，每个智能体单独决定是否允许，用到时在回答上标明（D5）。

知识库规模：按几万份文档、几百万个片段设计；扫描件走文字识别，入库是排队的后台任务，可暂停、重试，界面显示进度（D6）。

交付物：Spark 用的 ARM64 DEB 和 Mac（Apple Silicon）安装包，两者都带服务、可独立运行，先出这两个用于测试（D10）；之后是 Windows 桌面端和 Android APK。

离线：安装包自带界面、字体、文字识别和使用文档；模型做成离线资源包，从本地磁盘导入即可，不要求联网下载。只有联网搜索和云端模型需要网络（D11）。发布时附四种语言的使用文档，并内置在应用的帮助里（D12）。

升级：从第一个发行版起带签名升级与强制升级。服务与界面版本不一致时，客户端提示先升级，不做不兼容的操作。

## 4. 三个需求怎么落地

### 4.1 智能体即数据（需求 1）

一个智能体就是一份定义（AgentSpec），存在数据库里，可导入导出：

- 名称、头像、一句话简介
- 负责的任务、不负责的范围、遇到范围外问题怎么回应
- 系统提示词（由上面几项生成，可手改）
- 使用的模型与参数
- 挂接的知识库（可多个）、是否允许联网、可用工具（MCP）
- 回答规则：是否必须带出处、知识库没有时是否允许联网或直说不知道
- 开场白与示例问题
- 自测用例（问题 + 期望要点），改动后可一键回归

界面：点开智能体就是对话，配置收在「配置」按钮里（D13）。所有配置在界面里完成，不要求改文件。

### 4.2 知识库与联网（需求 2）

- 组织：知识库下可建多级文件夹。智能体的知识范围可以选到文件夹；每次提问还可以临时改范围；在文件夹页面可以直接只针对该文件夹（含子文件夹）提问。检索时按文件夹过滤，不是把所有资料混在一起。
- 入库：上传 → 解析（扫描件走文字识别）→ 分段 → 向量化 → 写入 LanceDB；任务排队执行，界面显示进度和失败原因，可暂停、重试。
- 检索：向量 + 关键词混合，取回后重排，带文档名和位置进入提示词。
- 回答模式（每个智能体可设，提问时可临时开关联网）：只用知识库 / 知识库优先、不足时联网 / 两者都用。
- 对话中上传的文件：文档、表格、图片、压缩包等，只在本次对话内使用，不进知识库；图片需要模型支持看图，不支持时改用文字识别提取内容并说明。
- 出处：知识库、本次上传、网页三类分开标注，可点开看原文片段；没有依据时明确说没有，不编。

### 4.3 对话生成智能体（需求 3）

内置一个「建造师」智能体，流程：

1. **访谈**：建造师按清单追问——这个智能体给谁用、处理什么问题、典型的问法、要用到哪些资料、哪些事不该做、回答的语气和格式。可以贴样例对话或上传资料。
2. **抽取**：对话结束（或用户说「可以了」）时，用结构化输出把访谈整理成 AgentSpec 草稿，同时生成一组自测用例。
3. **试答**：用草稿当场回答自测用例和用户临时提的问题，用户说哪里不对，建造师改定义后再试。
4. **发布**：确认后落库，成为一个独立智能体。

「独立」的含义（按投入从小到大，建议先做前两项）：

- 有自己的访问链接和独立的对话页面，不用进管理界面
- 有自己的 API 密钥和 OpenAI 兼容接口，可被其他系统调用
- 可暴露为 MCP 服务，被其他智能体当工具用
- 可导出为一个包（定义 + 知识库），导入到另一台机器的 CommonBot

如果「通话」指语音：在访谈环节加语音输入输出（识别 → 建造师 → 合成），后面的抽取、试答、发布不变，所以先做文字版不会返工。

## 6. 风险

- **Spark 上的实际速度**：统一内存大但带宽有限，100B 级模型可能只有每秒十几个字；建造师的抽取质量依赖强模型。要先在真机上测几款模型的速度和结构化输出的稳定性，再定默认模型。
- **ARM64 兼容**：推理后端和 Python 解析组件在 ARM64 + CUDA 上的支持要逐个确认。
- **复杂文档解析**：扫描件、表格密集的 PDF 质量取决于外部解析组件，P2 先保证文字版文档，复杂版面单独验收。
- **联网内容的安全**：网页里可能藏着针对模型的指令，抓取内容只当资料，工具调用需要白名单。
- **本开发环境没有 Spark**：这里只能编译和跑不依赖显卡的测试，推理、语音、安装包的真机验收要在你的设备上做。
